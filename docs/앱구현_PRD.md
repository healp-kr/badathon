## 1. 제품 정의 — 무엇을 만드는가

**"나에게 맞는 운동을, 갈 수 있는 곳에서, 실제로 하게 만드는 앱."**

세 단계가 끊기지 않고 이어지는 것이 이 제품의 전부다. 하나라도 끊기면 흔한 앱이 된다.

```
① 무엇을 할까    설문 13문항 → 선호 12유형 × 체력 16세그먼트 → 종목·강도·보완운동
        ↓          (국민생활체육조사 + 국민체력측정통계 · 이미 완성)
② 어디서 할까    현 위치 → 자치구 → 주변 체육시설 776곳 · 예약 가능한 곳 · 가는 방법
        ↓          (지도 위에서 고른다)
③ 했다           한 번 누르면 기록 → 주간 지침 달성률 → 다음 주 안내
        ↺          (기록이 쌓이면 추천이 보정된다)
```

**③이 이번에 새로 생긴 고리다.** 그리고 이 고리가 앞의 둘을 되먹인다 — 무엇을 실제로 했는지가
남아야 추천 가중치를 고칠 수 있고(F4), 자가평가 신뢰도도 검증할 수 있다(F2).

> **번호 표기 규칙**: 이 문서에서 **D는 §5의 시연 시나리오(D1~D5)에만 쓴다.** 로그가 쌓인 뒤
> 진행할 로드맵 항목은 **F**(Future)로 쓴다 — F2·F4·F5는 `발표_진행상황.md`의 D2·D4·D5와
> 같은 항목을 가리키되, 여기서 D를 재사용하면 D4(시연: 지도)와 F4(로드맵: 가중치 보정)가
> 뒤섞인다. **O는 §13 열린 결정 번호**로, 시연 시나리오·로드맵과 무관하다.

### 왜 기록이 '지침 달성률'이어야 하는가

단순한 운동 일지는 이미 넘친다. 우리가 다르게 할 수 있는 것은 **처방과 기록이 같은 근거를
쓴다**는 점이다. 추천 화면에서 "중강도 주 150분"을 말했으면, 기록 화면은 그 150분에 대해
얼마나 채웠는지를 말해야 한다. 둘이 따로 놀면 처방은 장식이 된다.

### 설계 원칙 — 날씨도 기록도 모델에 넣지 않는다

`serve()`는 **같은 입력이면 항상 같은 출력**을 낸다. 이 성질이 로그 분석과 `model_version`
추적의 근거다.

> **환경 컨텍스트와 운동 기록은 `serve()` 밖에서, 표현 계층의 후처리로만 적용한다.**
> 추천 목록(무엇을 추천하는가)은 바꾸지 않고 **표시 순서와 배지**만 바꾼다.
> 로그에는 원본 순위와 재정렬 후 순위를 **둘 다** 남긴다.

기록 기반 추천 보정(F4)은 로그가 쌓인 뒤 **파라미터를 다시 만드는** 방식으로 한다.
런타임에 개인 기록으로 점수를 흔들지 않는다 — 그러면 재현성이 깨진다.

## 4. 범위

### 포함

- 온보딩 13문항 (선택지는 `/api/survey-schema`가 정본)
- 결과 화면 — 유형 · 기반/익숙한/새로운 · 제외 · 처방 · 보완운동
- 위치 기반 지역 판정 + 지역 직접 선택 (S0-b)
- 환경 컨텍스트 배지 및 재정렬
- **지도 (S4)** — 자치구 경계 + 시설 핀 + 현재 위치 + 종목 필터
- **시설 상세** — 거리 · 전화 · 예약 링크 · 가는 방법(역·정류장·주차장)
- **운동 기록 (S5)** — 한 번 누르면 저장, 주간 지침 달성률, 최근 기록 목록
- **하단 탭** — 추천 / 지도 / 기록
- 시간대 혼잡도 (§8)
- 로그 11종 이벤트 전송

### 제외 (Non-goals)

| 항목 | 이유 |
|---|---|
| **서버 DB · 계정 · 로그인** | 기록은 `localStorage`. 시연에 계정 절차가 끼면 흐름이 끊긴다. 서버 로그(JSONL)는 별도로 이미 남는다 |
| **기기 간 동기화** | 위와 같은 이유. 폰을 바꾸면 기록이 사라진다는 점은 화면에 명시 |
| 지원 지역 확대 | 판정 구조는 전국 전제, **데이터는 2개 구만** (§7-2) |
| 웨어러블·헬스킷 연동 | 걸음 수·심박 연동은 v2. 지금은 수동 기록 |
| 푸시 알림 | 웹 푸시는 iOS 제약이 크다 |
| 협업 필터링·밴딧 | 로그가 쌓인 뒤 (F5) |

> **기록을 로컬에 두는 것은 타협이 아니라 선택이다.** 이 앱은 건강 관련 정보를 다루므로
> 서버에 개인 기록을 쌓는 순간 처리방침·보관기간·파기 절차가 따라붙는다. 시연 단계에서
> 그걸 대충 만드는 것보다, **기기 안에만 두고 그렇다고 밝히는 편이 정직하다.**

## 5. 시연 시나리오

시나리오는 **D**, 화면은 **S**로 구분한다.

| # | 입력 | 보여줄 것 |
|---|---|---|
| **D1** | 34세 남 · 저녁 헬스 · 무릎 불편 · *중구* | 저녁 고빈도 헬스형. 무릎 부담 종목이 **제외** 칸으로 |
| **D2** | 72세 여 · 매일 오전 걷기 · 자가평가 낮음 · *관악구* | 강도 상한이 내려가고 등산 제외. 보완운동에 의자 일어서기 |
| **D3** | **D1과 같은 답 + 비 오는 날** | 종목은 그대로인데 실내가 위로. **모델은 안 바뀌었다는 점을 말할 것** |
| **D4** | D1에서 **헬스 → 지도** | 지도에 주변 체력단련장 핀. 가장 가까운 곳 62m. **예약 가능한 곳은 예약 페이지로** |
| **D5** | D4에서 **[여기서 했어요]** | 기록 저장 → **기록 탭의 주간 달성률이 즉시 오른다**. "이번 주 90/150분" |

**D4·D5가 이번 단계의 핵심이다.** D1~D3이 "분석이 된다"를 보여준다면, D4·D5는
**"그래서 오늘 뭘 하면 되는지, 그리고 했는지"** 를 보여준다. 심사에서 갈리는 지점이다.

**D5 전에 밝힐 것 — 더미 기록(O12).** 기록 탭에 시연용으로 미리 넣어 둔 2~3건은 화면에
**"샘플"** 배지를 달아 실제 기록과 구분한다. 그리고 D5를 보여주기 전에 발표에서 먼저
말한다 — *"지금 두 건은 시연을 위해 미리 넣어 둔 샘플이고, [했어요]를 누르면 진짜 기록이
하나 늘어나는 걸 보여드릴게요."* 밝히지 않고 넘어가면 "그거 미리 조작한 거 아니냐"는
질문이 나올 수 있다 — 먼저 말하면 그 자체가 투명성의 증거가 된다.

**시연 시 지역 처리 — 장소가 두 구 밖인 것을 전제로 한다.**

1. 위치 권한 허용 → 지원 밖으로 판정 → **지역 선택 시트가 자동으로 열린다.**
   이 장면 자체가 설명이 된다: *"현재 위치를 읽지만, 데이터를 확보한 두 곳에서만 주변 정보를 줍니다"*
2. 시트에서 구를 고르고 진행. **여기서 두 구를 고른 근거를 한 문장으로 말한다**(§13 O6)
3. 무대에서 팝업을 피하고 싶으면 `?district=중구`로 시작 (2차 안전장치)

> 1번을 사고로 취급하지 말 것. **지원 범위를 밝히는 장면**으로 설계하면 약점이 아니라 범위 설정이 된다.

## 6. 화면 구조

```
        ┌─────────── 하단 탭 (온보딩 완료 후 노출) ───────────┐
        │      추천            지도            기록          │
        └───────┬──────────────┬───────────────┬────────────┘
                │              │               │
S0 진입 → S1 온보딩 → S2 결과 ─┤        S4 지도 ┤       S5 기록
  └ S0-b 지역 시트             └ S3 종목 상세 ──┘        └ S5-b 기록 추가
                                 └ S4-b 시설 없는 종목      S6 피드백
```

### S0. 진입 / S0-b 지역 선택 — *구현 완료*

위치 자동 판정 + 상시 변경. 상세는 §7-1.

### S1. 온보딩 — *구현 완료*

5스텝. 선택지는 `/api/survey-schema`에서만 온다. 나이로 체력 문항이 갈리고(65세),
`규칙적참여=false`면 운동 패턴 6문항을 건너뛴다.

### S2. 결과 — *구현 완료, 연결 추가*

| 블록 | 출처 | 표시 규칙 |
|---|---|---|
| 오늘의 조건 | `/api/context` | `구 이름 ▾`을 누르면 S0-b. 조회 실패 시 블록 숨김 |
| 나의 유형 | `선호유형`·`체력유형` | 확신도 1.2 미만이면 대안 병기. **"~일 수 있어요"** |
| 이미 하고 계신 운동 | `익숙한운동` | 비참여자에겐 "관심 있다고 하신 운동" |
| 비슷한 분들의 선택 | `새로운운동` | **"추천"이라고 쓰지 않는다** (§11) |
| 오늘은 빼 두었어요 | `제외종목` | 사유 그대로. 숨기지 않는다 |
| 강도·빈도 | `처방` | **여기 문구가 S5 달성률의 기준이 된다** |
| 보완 운동 | `보완운동` | `표현: "제안"`은 시각적으로 약하게 |
| **(신규) 종목 카드 액션** | — | **[주변에서 찾기] → S4**, **[했어요] → S5-b** |

- `점수` 숫자는 절대 노출하지 않는다
- `강도주의` 배지는 **필수** — 없으면 강도 상한이 무의미해진다

|---|---|---|

| 요가·체조·줄넘기 | "집에서도 할 수 있어요" + 보완운동 연결 | `시설불필요_비율` ≥30% |
| 등산·자전거 | 지도에 핀 없음 + 안내 한 줄 | 데이터 없음을 인정 |
| 축구·농구·체조·줄넘기·족구 | "학교·직장 시설 이용이 많아 검색 결과가 적을 수 있어요"를 **미리** | `인터페이스_명세.md` §4 |

**"결과 없음"을 화면에 그대로 내보내지 않는다**가 이 절의 유일한 요구사항이다.

## 7. 위치

### 7-1. 자동 판정 + 상시 변경 — *구현 완료*

| 경로 | 성격 | 우선순위 |
|---|---|---|
| 위치 자동 판정 | 기본값 | 낮음 |
| **지역 직접 선택** | 상시 노출, `localStorage` 저장 | **높음 — 자동 판정을 덮어쓴다** |

수동 선택을 폴백으로만 두지 않는 이유 셋: ① 시연 장소가 두 구 밖이다 ② 실제 사용자도
집·직장·운동하러 갈 동네가 다르다 ③ 실내 측위 오차로 옆 구가 잡힌다.

> **Geolocation은 HTTPS에서만 동작한다.** `localhost`는 예외지만 `http://<IP>:8000`으로
> 폰에서 열면 권한 창이 아예 안 뜬다. 시연은 터널(cloudflared 등)로 HTTPS를 붙인다.
> 지역 선택 시트가 있으므로 **HTTPS가 끝내 안 되면 위치 자동 판정만 빠지고 데모는 성립한다.**

- 좌표는 자치구 판정과 지도 중심점에만 쓰고 **서버에 저장하지 않는다.** 로그에는
  `district`와 `district_source`(auto/manual/override)만 남긴다

### 7-2. 지원 지역 — 구조는 전국, 데이터는 2개 구

경계 폴리곤 point-in-polygon으로 판정한다(`api/locate.py`). 외부 API도 라이브러리도 없다.
지역 정의는 `api/districts.json` **한 파일**이고, 구를 늘릴 때 행만 추가한다.

- **경계 밖이면 "지원 밖"이다. 최근접 보정을 하지 않는다** — 전국에 '중구'는 여럿이다
- 좌표 순서: GeoJSON은 (경도, 위도). 공개 함수는 전부 `(lat, lon)`을 받고 내부에서만 뒤집는다

### 8-3. 시간대 혼잡도

`생활인구_시간대요약`(96행)을 설문 Q7(운동 시간대)과 겹친다. **두 구가 정반대다.**

| | 평일 최고 | 평일 최저 |
|---|---|---|
| **중구** | **13시 42.5만** | 이른 아침 |
| **관악구** | 이른 아침 | **14시 39.7만** |

중구는 낮에 몰리는 업무지구, 관악구는 밤·새벽에 사람이 있는 주거지다. 같은 "저녁 7시 운동"이
두 구에서 뜻이 다르다.

- 추천 순서·강도에 관여하지 않는다. **정보 표시 전용이다**

## 9. 지도 (S4) — 신규

### 9-1. 무엇을 그리는가

```
┌──────────────────────────────────┐
│  [종목 ▾ 보디빌딩(헬스)]  [예약만] │  ← 필터
│                                  │
│      ● 현재 위치                  │
│    ◆ ◆   ◆        ◆              │  ← 시설 핀 (거리순 상위 20)
│  ╭──────────────╮                │
│  │  자치구 경계  │                 │  ← geo 폴리곤
│  ╰──────────────╯                │
├──────────────────────────────────┤
│  62m  피트니스 FM        [상세]   │  ← 하단 목록 (핀과 연동)
│  67m  프로틴짐PT 서울대입구점       │
└──────────────────────────────────┘
```

- **핀은 추천 종목으로 필터된다.** 지도를 열면 방금 본 종목이 기본 선택
- 종목 드롭다운으로 다른 추천 종목으로 갈아탄다 (추천 밖 종목은 넣지 않는다)
- 예약 가능한 시설은 **다른 색 핀** + 목록 상단 고정
- 핀 탭 → 하단 카드: 시설명 · 거리 · 전화 · 예약 링크 · **가는 방법** · **[여기서 했어요]**

### 9-2. 지도 라이브러리 — Leaflet + OSM 타일

| | 후보 | 판단 |
|---|---|---|
| A | 카카오/네이버 지도 SDK | 한글 지명이 정확. **API 키에 도메인 등록이 필요** — 터널 URL이 매번 바뀌는 시연에 취약 |
| **B** | **Leaflet + OpenStreetMap 타일** | **채택.** 키 불필요. 타일이 안 떠도 **경계 폴리곤과 핀은 그려진다** |
| C | 타일 없이 SVG 자체 렌더 | 완전 오프라인이지만 축척·이동 조작을 직접 만들어야 함 |

**B를 고른 결정적 이유는 실패 모드다.** 타일 서버가 막혀도 Leaflet은 우리 GeoJSON 경계와
핀을 그대로 그린다 — 배경만 비고 기능은 산다. 시연 중 네트워크가 흔들려도 화면이 죽지 않는다.

- Leaflet은 CDN이 아니라 **번들에 넣는다** (`web/ui` 의 npm 의존성). 시연장 네트워크를 믿지 않는다
- 타일 로딩 실패를 감지하면 "지도 배경을 불러오지 못했어요. 위치는 그대로 보입니다" 한 줄

### 9-3. 커버리지 — 이 화면의 난점

| 추천 상위 종목 | `geo/` 시설 | 처리 |
|---|---|---|
| 보디빌딩(헬스) | **243** | 풍부 |
| 골프 | **135** | 풍부 |
| 축구·수영·배드민턴·농구 | 7~16 | 소량이지만 있음 |
| 테니스+정구 | 시설 1 / **예약 8** | 예약이 본체 |
| **걷기·등산·요가·자전거** | **0** | **S4-b 대체 처리** |

**걷기는 12개 유형 전부에서 1위인 종목인데 시설이 0건이다.** 지도를 열었을 때 빈 화면이
되지 않도록 S4-b가 반드시 먼저 걸려야 한다.

- 반경 2km 우선, 3건 미만이면 구 전체로 확장하고 "구 전체에서 찾았어요" 표기
- `실내외구분`은 60% 결측이라 **화면에서 쓰지 않는다**(실내외 판단은 종목 속성으로만)
- 예약 시설은 좌표 49% 결측 → 좌표 없는 것은 **핀 없이 목록에만**

## 10. 운동 기록 (S5) — 신규

### 10-1. 기록 한 건

```jsonc
{
  "id": "uuid",
  "일시": "2026-08-13T19:20:00+09:00",   // KST 고정. §10-3 주 경계 판정의 기준
  "종목": "보디빌딩(헬스)",
  "강도": "중",                          // sport_master 기본값. 직접입력 흐름에서만 사용자가 바꿀 수 있다
  "시간분": 40,
  "장소": { "시설명": "피트니스 FM", "자치구": "관악구" },   // 지도에서 왔으면 자동
  "메모": "",
  "출처": "추천카드 | 지도 | 직접입력",
  "request_id": "...",            // 어느 추천에서 출발했는지 — 분석의 열쇠
  "model_version": "a9a2fb74e99c",
  "샘플": false                   // true면 시연용 더미(O12). 목록에 "샘플" 배지, 달성률 계산에는 포함
}
```

**저장 위치**: `localStorage` (`badathon.records`). 서버 DB는 만들지 않는다.
동시에 `sport_started`/`sport_completed` **로그 이벤트는 서버로 보낸다** — 기록 자체는
기기에 있고, 분석용 이벤트는 서버에 남는 구조다.

### 10-2. 입력은 두 번의 탭으로 끝난다

```
[했어요] → 시간 선택(20/40/60분 · 직접입력) → 저장
```

- 종목·강도·장소는 **이미 알고 있으므로 묻지 않는다.** 추천 카드나 지도 핀에서 왔기 때문이다
- 직접 입력(기록 탭 [+])만 종목을 고르게 한다
- 되돌리기(Undo) 한 번 제공 — 잘못 누른 것을 지우려고 설정에 들어가게 하지 않는다

**강도는 이 2탭 흐름에서 바꿀 수 없다.** `sport_master.csv`의 대표값을 그대로 쓴다.
직접입력(S5-b)에서 종목을 고르면 그 종목의 기본 강도가 채워지고, 거기서만 상/중/하로
바꿀 수 있다 — 빠른 기록 흐름을 2탭으로 지키기 위한 의도적 제한이다. 대신 달성률 화면에
이 강도가 **추정값**이라는 점을 밝힌다(§10-3).

### 10-3. 주간 달성률 — 처방과 같은 근거를 쓴다

`rules.json`의 baseline이 **"중강도 주 150분 이상(또는 고강도 75분)"** 이다. 이 문장이
**2:1 환산**을 이미 담고 있으므로, 근거 없이 만든 공식이 아니다.

```
주간 신체활동 점수(분) = Σ(중강도 시간) + Σ(고강도 시간) × 2
달성률 = 점수 / 150
```

**저강도 운동은 분 점수에 넣지 않는다(O10, 결정 완료).** 지침에 2:1(중:고) 환산만 있고
저강도 환산은 근거가 없다. 저강도 기록은 저장은 하되 점수 계산에서 빼고, **횟수로만**
"이번 주 저강도 n회" 형태로 별도 표시한다.

| 표시 | 내용 |
|---|---|
| **이번 주** | "90분 / 150분" + 막대. 월요일 시작. 중·고강도 기록만 반영 |
| **근력 운동** | "2일 / 주 2일" — 지침의 별도 권고라 따로 센다 |
| **저강도 활동** | "이번 주 n회" — 점수에는 안 들어가지만 기록은 목록에 남는다 |
| 최근 기록 | 날짜·종목·시간·장소 목록 (강도 무관 전부) |
| 연속 주차 | "3주째 채우는 중" (달성한 주만) |
- 달성률 100%를 넘겨도 "충분해요"라고 멈추게 하지 않는다. WHO는 중강도 300분까지 권장 범위다
- **미달성을 질책하지 않는다.** "이번 주는 60분 하셨어요"까지만. 건강 앱이 죄책감을 파는 것은
  이 프로젝트의 문구 원칙(§11)에 어긋난다

**강도 라벨의 한계가 달성률에 그대로 넘어온다.** 점수 공식(Σ중 + Σ고×2)은 기록마다 붙은
`강도` 값을 그대로 신뢰한다. `강도라벨_재검토.md`가 이미 정리했듯 대표 MET이 "세게 했을 때"
기준으로 쏠려 있고(데모까지는 현행 유지로 결정됨, 같은 문서 §5), 2탭 흐름에서는 사용자가
이 값을 고칠 수도 없다(§10-2). 즉 **달성률도 "세게 했다고 가정했을 때의 점수"** 다. S2의
강도 문구 원칙과 마찬가지로, 달성률 화면에도 이 가정을 한 줄로 밝힌다 — 예:
"기본 강도 기준으로 계산돼요."

**주 경계는 KST 월요일 00:00시부터다.** 기록의 `일시`는 타임존 오프셋(`+09:00`)을 반드시
포함하고, 이 값을 KST로 변환한 뒤 그 주(월요일 00:00:00 ~ 다음 월요일 00:00:00 직전)에
속하는 기록만 "이번 주" 합산에 넣는다. 자정 근처 기록이 오차 없이 한 주로만 귀속되도록
프론트·서버가 이 규칙을 그대로 따른다.

**근력 운동 판정은 종목 화이트리스트로 한다(O13, §13).** `sport_master.csv` 35종목 중
지침이 말하는 "근력운동"(저항·웨이트 트레이닝)에 모호함 없이 해당하는 건 **보디빌딩(헬스)**
하나뿐이다. 초기값은 이 1종목만 근력 운동으로 카운트하고, 목록을 넓히려면 종목별 확인이
먼저 필요하다 — 지금은 확대하지 않는다.

### 10-4. 기록이 되먹이는 것

| 쓰임 | 시점 |
|---|---|
| `sport_completed` 로그 → 추천 가중치 보정(F4) | v2. **지금 안 남기면 소급이 안 된다** |

| "무릎이 아프니 등산 금지" | "무릎이 불편하다고 하셔서 빼 두었어요" |
| **"목표 미달성"·"오늘도 안 하셨네요"** | **"이번 주는 60분 하셨어요"** |
| **"칼로리 소모 320kcal"** | 쓰지 않는다 — 체중·효율 가정이 필요해 근거가 없다 |

- 확신도 1.2 미만이면 대안 유형을 반드시 함께 보인다(배정 모호 30.2%)
- 면책 문구는 모든 화면 하단 고정
- **기록 화면에 "폰을 바꾸면 기록이 사라집니다"를 명시한다.** 로컬 저장은 선택이지 사고가 아니다

## 12. 백엔드 계약

`serve()`를 임포트하는 곳은 `web/main.py` 한 곳뿐이다. 프론트는 HTTP만 안다.
스택은 **FastAPI + uvicorn**.

| 엔드포인트 | 용도 | 상태 |
|---|---|---|
| `GET /api/survey-schema` | 문항·선택지 (`value`/`label` 분리) | **완료** |
| `GET /api/districts` | 지원 지역 목록 | **완료** |
| `GET /api/locate` | 좌표 → 자치구 | **완료** |
| `GET /api/context` | 오늘의 조건 (10분 캐시) | **완료** |
| `POST /api/serve` | 온보딩 → 추천 + 환경 합성 + 로그 3종 | **완료** |
| `GET /api/facilities` | 종목별 시설·예약·접근성 | **완료** |
| `GET /api/crowding` | 시간대 혼잡도 | **완료** |
| `POST /api/events` | 상호작용 로그 | **완료** |
| **`GET /api/map/boundary`** | 자치구 경계 GeoJSON | **신규** |
| **`GET /api/map/facilities`** | 지도용 핀 묶음(종목·구·반경) | **신규** |

- 응답의 `request_id`를 프론트의 모든 후속 이벤트에 실어 보낸다. 조인 키가 없으면 분석이 불가능하다
- 좌표는 `/api/locate`에서만 받고 그 자리에서 버린다
- **기록 저장 엔드포인트는 만들지 않는다.** `localStorage` + `sport_completed` 이벤트로 충분하다

**서버 기동 시 가드레일**: 설문 선택지가 모델 범주와 어긋나면 **서버가 뜨지 않는다**
(`web/schema.py`의 `validate()`). 조용한 실패를 시끄러운 실패로 바꾼 장치다.

## 14. 작업 순서

```
완료 ──── 배정·추천·serve·로그 · 위치·환경 · geo · 백엔드 8종 · S0·S0-b·S1·S2
             │
             ├─→ M1 지도 엔드포인트 2종 ─┐
             │                          ├─→ M3 S4 지도 화면 ─→ M4 시설 상세
             ├─→ M2 Leaflet 로컬 배치 ──┘                          │
             │                                                     ↓
             └─→ R1 기록 저장소 ─→ R2 S5 기록 화면 ─→ R3 [했어요] 연결 ──┘
                                        │
                                        └─→ N1 하단 탭 ─→ 리허설
```

| 순서 | 작업 | 선행 |
|---|---|---|
| 1 | **M1** `/api/map/boundary` · `/api/map/facilities` | 없음 |
| 2 | **M2** Leaflet 파일 로컬 배치 + 타일 실패 폴백 | 없음 |
| 3 | **N1** 하단 탭 (추천/지도/기록) | 없음. 먼저 넣어야 화면 이동이 생긴다 |
| 4 | **M3** S4 지도 — 경계·핀·현재 위치·종목 필터 | 1, 2, 3 |
| 5 | **M4** 시설 상세 카드 + 예약 링크 + 가는 방법 | 4 |
| 6 | **R1** 기록 저장소(localStorage) + 달성률 계산 | 없음 (O10·O12·O13 결정 완료) |
| 7 | **R2** S5 기록 화면 — 주간 달성률·최근 기록 | 6 |
| 8 | **R3** [했어요] 버튼을 S2·S3·S4에 연결 + `sport_completed` 로그 | 6, 7 |
| 9 | S4-b · S6 피드백 · §11 문구 정리 | 4, 7 |
| 10 | **HTTPS 터널 + 폰 실기 확인** | **사용자** |
| 11 | D1~D5 리허설 · 실패 경로 점검 | 전부 |

**10을 뒤로 미루지 말 것.** HTTPS가 없으면 위치 기능은 폰에서 조용히 죽고, 데스크톱
`localhost` 테스트에서는 드러나지 않는다.

**11의 실패 경로 점검 여섯**: ① 위치 권한 거부 ② 지원 밖 좌표(**실제 시연 장소 좌표로**)
③ 공공데이터포털 5xx ④ **지도 타일 불통** ⑤ 시설 0건 종목에서 지도 열기
⑥ 기록이 하나도 없는 상태의 기록 탭. 전부 **빈 화면이 아니라 무언가를 보여줘야** 한다.
