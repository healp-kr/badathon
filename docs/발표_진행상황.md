## 1. 배정 층 — "학습이 없다"가 핵심

### 왜 모델 서버가 필요 없는가

LCA는 생성모형입니다. 클래스 사전확률과 조건부 응답확률만 있으면 임의의 응답에 대해
사후확률을 **직접 계산**할 수 있습니다.

```
log P(유형 c | 응답 x) ∝ log π_c + Σ log θ(문항 j, 유형 c, 응답값)
```

그래서 이 단계의 과제는 "분류기 학습"이 아니라 **파라미터 추출과 문항 축약**이었습니다.
결과적으로 **학습·GPU·클라우드·모델서버가 전부 불필요**합니다. JSON 파라미터 파일을 읽어
계산만 하므로, 같은 입력은 항상 같은 결과를 냅니다.

### 만든 것

| 파일 | 내용 |
|---|---|
| `assignment/params/preference_model.json` | 12클래스 사전확률 + 6문항 조건부확률 + 범주 레벨 |
| `assignment/params/fitness_model.json` | 4하위집단 × 5축 중심 4개 + 신체조성 회귀계수 |
| `assignment/assign.py` | `assign_preference()` · `assign_fitness()` · 라우팅 |

### 검증 결과

> **원본 응답자 6,602명 재현 100%** (선호축) · **중심 재배정 99.9%** (체력축)
> 테스트 33항목 통과 — `python assignment/test_assign.py`

원본 데이터를 그대로 넣으면 원래 붙은 라벨이 그대로 나옵니다. "됐는지 안 됐는지"가
명확한, 정답이 있는 작업이었습니다.

### 체력축의 실제 문제와 해결 경로

**라이브 사용자는 국민체력100 측정을 받지 않습니다.** 악력계도 왕복오래달리기도 없습니다.

- **폐기한 경로** — 키·몸무게로 체력을 회귀 추정. 실측 R²가 0.07~0.38로 낮았습니다.
  z-score가 이미 연령대×성별 내부 표준화라 나이·성별의 정보가 제거돼 있는 것이 원인입니다.
- **채택한 경로** — **자가평가 분위 매핑.** 축별 5단계 자가평가를 누적 응답비율로 z 변환해
  5축 벡터를 만들고, 하위집단별 K-means 중심에 최근접 배정합니다.
  신체조성 축만 키·몸무게 회귀로 추정합니다(R² 0.50~0.58).

**예상 정확도 (측정값)** — 자가평가 신뢰도 r에 전적으로 좌우됩니다.

| | 성인 남 | 성인 여 | 노인 남 | 노인 여 |
|---|---|---|---|---|
| 완벽(r=1.0) 천장 | 77.6% | 75.2% | 76.7% | 75.2% |
| r=0.7 | 57.5% | 57.7% | 57.4% | 59.5% |
| r=0.5 | 48.1% | 49.7% | 49.8% | 52.1% |
| 최빈 클래스 찍기 | 32.0% | 28.6% | 28.5% | 33.4% |

> **r은 현재 데이터로 잴 수 없습니다.** 국민체력측정 데이터에 자기보고 문항이 하나도 없기
> 때문입니다. 출시 후 일부 사용자에게 자가평가와 간이 측정을 함께 받는 것이 유일한 검증
> 경로입니다(§5 D2).

이 숫자 때문에 **결과 화면에서 단정적 표현을 쓰지 않기로** 했습니다. 배정 모호 비율이
전체 30.2%이고, 확신도 1.2 미만이면 대안 세그먼트를 함께 노출합니다.

### 라우팅 — 경계가 셋 다릅니다

| | 선호 모델 | 체력 모델 | 화면 표시 |
|---|---|---|---|
| 노인 경계 | **60세** | **65세** | **60세** |

- 60~64세 → 선호는 노인, 체력은 성인 모델, 화면에는 노인. **의도된 설계**입니다(측정
  프로토콜이 19–64 / 65+로 나뉘어 있어 모델을 다시 태울 수 없습니다).
- 19세 미만 → 체력 유형 없음, 선호만
- 규칙적 참여 "아니오" → 선호 유형 없음, 관심 종목 기반으로 처리

## 2. 추천 층 — 두 번의 설계 전환이 핵심

### 전환 ① 도메인 전문가 없이 진행 (2026-08-07 결정)

체육 전공자 검토를 확보할 수 없었습니다. 이 병목을 두 가지로 해소했습니다.

**근거를 공개 지침 인용으로 대체.** "누군가가 그렇게 생각했다"가 아니라 "어느 문서 어디에
그렇게 쓰여 있다"로 만들었습니다.

| 자료 | 우리가 쓰는 부분 |
|---|---|
| 한국인을 위한 신체활동 지침서(2023) · 보건복지부 | 성인·노인 권장 빈도·강도 국내 기준 |
| 노인 운동 · 질병관리청 국가건강정보포털 | 유산소·근력·균형·유연성 각각의 빈도·강도 |
| 노인 낙상 예방 운동 프로그램 운영매뉴얼 · 질병관리청 | 평형·하지근력 운동의 구체적 구성(의자·매트만) |
| WHO Guidelines on Physical Activity (2020) | 65+ 다요소 운동 권고 |
| Compendium of Physical Activities (2024) | 종목별 MET → 강도 태깅의 객관적 근거 |

**의학적 판정을 설계에서 덜어냄.** 안전 처리는 세 가지로만 구성됩니다.

1. **사용자 자가 제외** — "무릎 통증에 등산 금지"를 우리가 판정하지 않습니다. 사용자가
   불편 부위를 고르면 해당 부담 태그 종목을 숨깁니다. **판단 주체가 사용자로 이동합니다.**
2. **보수적 기본값** — 지침에 명시된 것만 자동 적용(주 1회부터 시작·점진 상향, 확신도가
   낮으면 낮은 쪽 강도, 노인+전반적 저조형은 고강도 종목 제외)
3. **상담 안내 문구** — 질병관리청이 명시한 상담 필요 상황을 그대로 노출

> 이 결정으로 **출시 전 크리티컬 패스에서 도메인 검토가 빠졌습니다.**

### 전환 ② 추천을 두 갈래로 분기

기존에는 같은 유형이면 누구에게나 같은 결과가 나왔습니다. 이제 세 묶음으로 나갑니다.

| 묶음 | 정의 |
|---|---|
| **기반 활동** | 걷기. 어느 유형에서든 1위라 다른 종목을 밀어내므로 추천 칸에서 분리 |
| **익숙한 운동** | 사용자가 고른 종목 중 지금 할 수 있는 것 |
| **새로운 운동** | 고르지 않은 종목 중 같은 유형에서 적합도가 높은 것 |

얻은 것이 넷입니다.

- 개인 응답이 추천에 **실제로** 반영됩니다
- **걷기 편중이 완화**됩니다 — 걷기를 고른 사람은 걷기가 익숙한 쪽으로 빠지고, 새로운 쪽에
  다른 종목이 올라옵니다
- **비참여자 분기가 자연히 해결**됩니다. 선호 유형이 없어도 관심 종목만으로 익숙한 갈래가
  성립하므로, 별도 온보딩 화면이 불필요해졌습니다
- 두 갈래의 클릭률을 비교하면 **가중치의 유효성을 측정**할 수 있습니다

### 파이프라인 — 두 축을 저울질하지 않고 순서대로

```
① 종목 후보     ← 선호축만 (데이터 기반)
② 두 갈래 분기  ← 고른 종목 / 고르지 않은 종목
③ 안전 필터     ← 불편 부위·연령·강도 상한 (하드 컷, 점수 무시)
④ 강도·빈도     ← 체력축 (공개 지침)
⑤ 보완 운동     ← 체력축 약한 부위 1~2개
```

**체력축은 종목 선택에 관여하지 않습니다.** 강도 조절과 보완 운동에만 씁니다.

## 3. 앱 연동 — 앱이 알아야 할 것은 함수 하나

```python
from serve import serve
result = serve(payload)
```

앱과 GIS 레이어는 `인터페이스_명세.md` 하나만 보면 됩니다. 내부 구조는 몰라도 됩니다.

**입력** — 나이·성별만 필수. 나머지는 있으면 좋고, 6문항 중 3문항만 있어도 동작합니다
(확률만 낮아집니다).

**출력** — 라우팅 / 선호유형 / 체력유형 / 기반활동 / 익숙한운동 / 새로운운동 / 제외종목 /
처방 / 보완운동 / 시설검색조건 / 안내 / 면책.

**시설은 이 API가 찾지 않습니다.** "무엇을 찾아야 하는가"까지만 알려주고 GIS 레이어에
넘깁니다. 종목별로 검색 키워드·대분류·신뢰도·시설불필요 비율을 함께 줍니다.

> 축구·농구·체조·줄넘기·족구는 학교·직장 시설 이용이 많아 세부시설 응답률이 낮습니다.
> 이 종목들은 `신뢰도: 낮음`으로 표시되며, **검색 결과가 없어도 이상한 것이 아닙니다.**

**결과 추적** — 파라미터 파일 해시가 `model_version`으로 자동 스탬프됩니다. 파라미터를
바꾸면 버전이 자동으로 바뀌므로 비교 분석의 기준선이 생깁니다.

**검증** — 진입점 테스트 32항목 통과 (계약·경계·검증·로그·재현성).

### 조용한 함정 하나

설문 선택지 문자열과 모델의 범주 레벨이 **한 글자라도 다르면 그 문항은 조용히 무시됩니다.**
에러가 나지 않고 배정 정확도만 떨어지므로 더 위험합니다. 매핑 표를 코드에 하드코딩하지 않고
**데이터 파일로 두어 양쪽이 같은 파일을 참조**해야 합니다.

## 6. 알려두어야 할 한계 — 화면 문구에 반영

- **체력 유형 정확도 50% 내외.** 자가평가 신뢰도에 좌우되며 현재 데이터로 측정 불가.
  "당신은 저조형입니다" 같은 단정을 쓰지 않고, "또래와 비교하면 ○○ 쪽이 약할 수 있어요"
  수준으로. 확신도가 낮으면 대안 유형을 함께 노출합니다.
- **추천 근거는 인과가 아닙니다.** "비슷한 분들이 많이 하십니다"는 그들이 이미 하는 것이지
  그들에게 좋은 것이 아닙니다. **"추천"보다 "비슷한 분들의 선택"이 정확한 표현**입니다.
- **선호 유형은 확률입니다.** 하드 라벨만 쓰지 말고 2순위를 함께 활용합니다.
- **근거가 없는 항목** (구현하되 "제안"으로 표현, 전문가 확보 시 1순위 검토):
  순발력 보완 운동(v1 제외) · 종목별 부담 부위 태깅 · 12개 종목의 MET · 점수 가중치 전반.
